## 二、 受平台限制无法实现项清单（共 3 项）

以下 3 项能力经核查属于受思源宿主或运行环境限制无法在插件内直接实现，已在文档中写明限制来源与当前替代方案，不计入开发缺陷：

1. **[PLAT-01] 思源内核正式 FSRS 评分逆向回退**
   - **限制来源**：思源笔记内核 `/api/riff/reviewRiffCard` 接口在提交评分并更新卡片 FSRS 稳定性（Stability）、难度（Difficulty）与下次到期时间（Due）后，未提供逆向撤销或恢复上一次 FSRS 算法状态的内核 API。
   - **当前替代方案**：插件通过本地撤销历史栈（`ReviewHistorySnapshot`）召回上一张卡片供用户重新自评覆盖，并通过 `revlogAppended` 守卫精确回滚插件本地 `revlog.json` 中的统计记录。
2. **[PLAT-02] 移动端（Android/iOS）与纯浏览器宿主本地解析 Anki `.apkg` 压缩包**
   - **限制来源**：Anki `.apkg` / `.colpkg` 内含 SQLite 数据库文件与 deflate 二进制流，解析依赖 Node.js 原生模块 `node:sqlite` 与 `node:zlib`；思源移动端与纯浏览器前端不包含 Node.js 运行时。
   - **当前替代方案**：通过 `src/api/anki-host.ts` 的 `detectSqlite()` 动态探测宿主能力，在非 Node 宿主隐藏文件选择按钮并显示明确原因说明，引导用户在桌面端思源完成 `.apkg` 导入后通过思源同步或 `.lvcards` 分享包流转至移动端。
3. **[PLAT-03] 内核插件（`kernel.js`）跨设备同步与断线重放广播**
   - **限制来源**：思源 3.8.x Goja 内核插件运行时的 `api.rpc.broadcast` 仅向当前同一 Kernel 进程下的已连接前端发送易失内存消息，不支持断线消息队列缓存或跨设备云端实时推送。
   - **当前替代方案**：将考试计划等状态事实源保存在客户端插件持久化文件（`data/storage/petal/siyuan-lv-cards/*.json`），RPC 广播仅作为同机多窗口即时刷新信号，前端重连或切回可见时自动重读磁盘快照对齐。

## 三、 合并去重后的统一可执行待办池（共 18 项：功能实现 9 项 + UI 审查 9 项）

> **评分与优先级规则**：
> - **影响面（Impact）**：`1`（极小/单控件细节）~ `5`（核心主流程/数据正确性/安全边界）
> - **频率（Frequency）**：`1`（极低频边缘操作）~ `5`（每次复习/高频必经路径）
> - **成本（Cost）**：`1`（小：单文件或少量代码直改） / `2`（中：跨 2~3 个模块联动与测试） / `3`（大：需新设计交互流或多模块重构）
> - **优先级公式**：$\text{得分} = \frac{\text{影响面} \times \text{频率}}{\text{成本}}$。同根因问题已合并为单一条目并标注关联表现。

### 【TODO-01】[功能 · 缺陷] 复习页签挂载遗漏 `customCardCss`、`checkinItemId`、`leechThreshold` 三项设置映射，且水蛭卡横幅阈值硬编码为 5
- **合并关联项**：自定义卡面 CSS 在复习中不生效、小驴打卡生态联动完成后不触发打卡、自定义疑难卡（水蛭卡）遗忘阈值在复习中不生效。
- **问题描述（可复现）**：
  - **位置**：`src/bootstrap/tab-registrars.ts:571-597`、`src/ui/review.svelte:2268, 2295`、`src/core/review-queue-pipeline.ts:39`。
  - **操作步骤**：
    1. 打开“设置”，在“外观卡面”填写“自定义卡面样式（CSS）”，在“学习节奏”设置“小驴打卡生态联动 ID”并将“疑难卡标记阈值”改为 `8`，点击保存；
    2. 打开“开始复习”页签进行复习直至完成本场；
    3. 观察卡面样式、水蛭卡预警横幅触发时机以及完成屏打卡联动。
  - **当前表现**：`registerReviewTab` 的 `settings()` 回调仅返回了 25 个字段，漏传了 `customCardCss`、`checkinItemId` 和 `leechThreshold`，导致 `review.svelte` 中 `eff().customCardCss` 与 `eff().checkinItemId` 恒为 `undefined`（自定义 CSS 与打卡联动在生产环境完全失效）；同时 `review.svelte:2295` 硬编码 `{#if current && (current.lapses ?? 0) >= 5}`、`review-queue-pipeline.ts:39` 硬编码 `isLeechCard(c, 5)`，无视用户设置的 `leechThreshold`。
  - **期望表现**：`registerReviewTab` 完整透传上述三项设置；`review.svelte` 与 `applyQueuePipeline` 统一读取 `eff().leechThreshold ?? 8`（或设置值）判定水蛭卡。
- **解决方案**：
  1. 在 `src/bootstrap/tab-registrars.ts:571-597` 的 `settings()` 返回对象中补齐 `customCardCss: plugin.settings.customCardCss`、`checkinItemId: plugin.settings.checkinItemId`、`leechThreshold: plugin.settings.leechThreshold`；
  2. 在 `src/core/review-queue-pipeline.ts` 的 `QueuePipelineOptions` 增加可选 `leechThreshold?: number` 并传给 `isLeechCard(c, options.leechThreshold ?? 5)`；
  3. 在 `src/ui/review.svelte:850` 与 `:2295` 统一使用 `eff().leechThreshold ?? 5` 判定水蛭卡预警横幅。
- **成本**：**小（1）**——仅涉及 `tab-registrars.ts`、`review-queue-pipeline.ts` 与 `review.svelte` 三处属性映射与参数透传。
- **风险**：原本未修改设置（默认 `leechThreshold: 8`）的用户，若统一走设置值，水蛭卡触发阈值将从硬编码 5 变为设置值 8；需同步核对 `tests/benchmark-fusion.spec.ts` 默认参数兼容。
- **优先级计算**：影响面 `5`（3 项核心设置完全失效）× 频率 `5`（每次复习必经）÷ 成本 `1` = **25.0（P0）**。
