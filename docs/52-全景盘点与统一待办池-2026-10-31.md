## 二、 缺陷排查记录（含可复现步骤与实测证据）

按项目实际情况排查崩溃、状态、数据、交互、集成五类问题（崩溃类经 `tests/store-startup-fault.spec.ts` 与 `tests/api-response.spec.ts` 实测无未捕获异常，直接跳过无问题项）：

### 2.1 [数据类 / 交互类] 撤销（Undo `p`/`q`）无条件回滚 `revlog` 误删历史记录，且 `Ctrl+D` 归档不可撤销
- **位置**：`src/ui/review.svelte:506-525, 1205-1255`、`src/core/review-history.ts:20-65`
- **复现步骤**：
  1. 在复习中对卡片 A 进行正式评分（写入 `revlog.json`）；
  2. 同一张卡片 A 在遗忘重现队列（`lvRequeue`）、Cram 突击模式（`cramActive`）或后续会话中被点击“跳过”（`skip`）；
  3. 按快捷键 `p` / `q` 或点击工具栏“撤销”按钮；
  4. **原表现**：`undoHistory()` 无条件执行 `ctx.rollbackRevlog?.(snap.current?.cardID)`，从 `revlog` 中反向查找并删掉了卡片 A 此前正式写入的评分记录。此外，按 `Ctrl+D` 解散归档卡片（`dismissCurrentCard`）未压入 `history` 栈，且 `dismissBusy` 未纳入 `actionBusy`，误按后无法按 `p`/`q` 撤销恢复。
- **修复与实测验证**：在 `ReviewHistorySnapshot` 中增加 `revlogAppended` 与 `dismissedBlockID` 字段，仅当正式评分实际调用 `ctx.appendRevlog` 后置 `revlogAppended = true`；撤销 `Ctrl+D` 时自动将 `custom-lv-dismissed` 重置为空并恢复卡片；`tests/review-async-actions.spec.ts` 新增 2 项专项回归测试全部通过。

### 2.2 [状态类 / 数据类] Cram 考前突击快刷模式污染正式每日会话（`session-state.json`）并误调内核跳过
- **位置**：`src/ui/review.svelte:337-344, 797-820, 1274-1296, 1341-1365, 1856-1914`、`src/index.ts:2718-2731`
- **复现步骤**：
  1. 从总览点击“考前突击快刷”进入 `cramActive = true` 会话，评完或跳过若干今日到期卡；
  2. 返回总览后再点击正常“开始今日复习”；
  3. **原表现**：Cram 模式下 `rate()` 与 `skip()` 仍调用 `persistSession()` 将突击卡写入 `session-state.json` 的 `reviewedIDs`，且 `skip()` 仍调用内核 `skipReviewRiffCard`；同时已挂载的复习页签在收到无 `cram` 字段的切换请求时未重置 `cramActive`，导致突击快刷过的到期卡在正式复习中被跳过漏学。反之，先正式复习再点突击快刷时，已复习卡也被过滤导致无法突击。
- **修复与实测验证**：`cramActive` 下禁止写入或读取正式 `session-state.json`，`skip()` 在 `cramActive` 下仅做本地跳过不调内核；`openTabOf(TAB_REVIEW)` 显式传递 `cram: Boolean(data?.cram)` 并在模式切换时隔离重置进度；`tests/review-async-actions.spec.ts` 实测通过。

### 2.3 [集成类] 复习页签挂载遗漏 `burySiblings` 设置映射，分享包导出器版本常量滞后
- **位置**：`src/bootstrap/tab-registrars.ts:571-596`、`src/core/lvcards-package.ts:89`
- **复现步骤**：
  1. 在设置中开启/关闭“同源兄弟卡防剧透推迟”（`burySiblings`），打开复习页签，`registerReviewTab` 的 `settings()` 回调未包含 `burySiblings` 字段；
  2. 导出 `.lvcards` 分享包，JSON 内 `generator` 固定为 `"siyuan-lv-cards/v0.210.3"`。
- **修复与实测验证**：在 `registerReviewTab` 补齐 `burySiblings` 映射；在 `src/core/lvcards-package.ts` 导出 `PLUGIN_VERSION` 常量并接入 `scripts/check-versions.mjs` 四处一致性门禁。

## 三、 核心功能全链路核查与半成品识别

逐项核验核心功能的 **输入 → 处理 → 持久化 → 重载后仍在 → 异常后可恢复** 完整链路，结论严格分为 **已实现且可用**、**技术上可行但未做**、**受平台限制无法实现** 三类：

### 3.1 本轮识别并补全的半成品（均已升级为「已实现且可用」）

1. **复习端星标收藏（`starredCardIDs`）跨会话持久化断裂**：
   - **原状态**：`src/ui/review.svelte` 中 `starredCardIDs` 仅为内存 `new Set()`，既未从 `plugin.settings.starredCards` 初始化，也未在按 `*` 时写回设置，导致复习中收藏的星标卡在重载后丢失、在卡片管理器“星标卡”筛选中不可见。
   - **补全实现**：在 `registerReviewTab` 注入 `getStarredCardIDs` 与 `toggleStarCard`，支持 `blockID` 与 `cardID` 双键对齐、跨会话持久化及 `settings-changed` 热同步。
2. **解散归档卡（`custom-lv-dismissed="true"`）跨会话过滤缺失**：
   - **原状态**：`src/core/incremental-learning.ts` 定义了 `filterDismissedFromQueue`，但出题管线从未调用，导致按 `Ctrl+D` 归档的卡片在次日或重载后重新混入复习队列。
   - **补全实现**：`src/core/review-queue-quality.ts` 查询 `SELECT id, ial, markdown FROM blocks` 时解析 `ial` 中的 `custom-lv-dismissed="true"`，自动调用 `filterDismissedFromQueue` 过滤且不计入结构坏卡。
3. **完成屏（Done Panel）“强化这批遗忘卡”与“立即专项练习星标卡”占位实现**：
   - **原状态**：`src/ui/review.svelte` 中两个回调仅写了 `() => { cramActive = true; void loadQueue(); }`，未筛选遗忘卡或星标卡，且因 `reviewedIDs` 拦截导致点击后无卡可练；同时当卡组内既有到期卡又有未到期卡时，Cram 模式因 `cards.length === 0` 条件限制漏拉未到期卡，按笔记本/文档范围突击时误调全局接口。
   - **补全实现**：在 `review.svelte` 维护 `sessionCardMap`、`forgottenCardIDs` 与 `sessionStarredCardIDs`，实现 `startCramForgotten()` 与 `startCramStarred()` 精准拉起专项突击队列；Cram 模式支持 `deck:` / `notebook:` / `doc:` / `all` 全范围去重合并拉取。
4. **总览 7 日负载平滑开关未持久化且未联动预测日历**：
   - **原状态**：`src/ui/dashboard.svelte` 中 `smoothLoadEnabled` 重载即丢，且切换时未同步更新下方 14 日预测日历。
   - **补全实现**：持久化 `smoothLoadEnabled` 状态，开启平滑时同步更新 7 日柱状图与 14 日学习日历预测数据。
