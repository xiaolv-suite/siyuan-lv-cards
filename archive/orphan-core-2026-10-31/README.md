# 归档说明 · 未接入运行时的实验性核心模块（2026-10-31）

> 归档依据：[docs/54-优化路线与开发方向-2026-10-31.md](../../docs/54-优化路线与开发方向-2026-10-31.md) 阶段 A · F3。
> 数据保护约定：只迁移归档，不删除代码或 Git 历史。本目录不在 `tsconfig.json` 与 `vitest.config.ts` 的 `include` 范围内，不参与日常编译、构建与测试。

## 为什么归档

对 `src/index.ts`、`src/kernel.ts` 与 `src/chunks/*.ts` 做完整传递依赖可达性扫描后，确认这 **42 个 `core` 模块（共 10,360 行）**及 **40 个专属单元测试文件**在生产运行时与界面中均不可达（只有单测或彼此之间相互引用）。把它们留在主线里会带来三个问题：
1. 每次排查、类型检查与单测都要为空转代码买单；
2. 历史文档与更新摘要曾将其中部分模块误写为已上线功能；
3. 干扰后续阶段 B/C 对真实在役模块的判断。

## 目录结构与恢复方式

- `core/`：42 个原 `src/core/*.ts` 模块（包括 AI/Agent 治理层、标量数值答案政策、两版成就导出、返场模拟、策略实验、离线操作队列、同步冲突向导等）。
- `tests/`：40 个仅测试上述模块的 `*.spec.ts` 文件。

后续若某一具体真实场景需要重新启用某个模块，直接执行：

```bash
git mv archive/orphan-core-2026-10-31/core/<模块名>.ts src/core/<模块名>.ts
git mv archive/orphan-core-2026-10-31/tests/<测试名>.spec.ts tests/<测试名>.spec.ts
```

并在完成真实界面接线与宿主走查验收后再写入 `README.md`。
